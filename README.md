# FPGA Project Reader

面向 FPGA 工程师的工程阅读 Skill。把现有工程交给 AI 助手，获得带源码证据的用途说明、有效配置、模块职责、数据路径、时钟复位和测试结构；需要时，再生成离线交互框图与时钟树。

**第一次使用建议：先快速阅读，再对感兴趣的模块深入分析。** 默认快速模式，不会因为工程较大而自动升级为全工程详细分析。

## 1. 第一次使用

确认 Skill 已安装，并让助手能够访问待分析工程。在对话中发送以下内容，将工程路径替换为自己的实际路径：

```text
请使用 $fpga-project-reader，以快速模式阅读 D:/FPGA/MyProject。
说明工程用途、有效配置、主要模块、时钟复位和测试结构。
每项结论附来源；无法确认的信息标为未知。
```

助手会定位工程入口和有效顶层，阅读主要路径，并生成报告。完成后，先打开工程目录下的 `fpga-reader-report/INDEX.md`，再进入快速概览。

工程有多个 revision、构建目标或文件集时，建议一并说明：

```text
请使用 $fpga-project-reader 阅读 D:/FPGA/MyProject，采用快速模式。
工程入口为 board.qpf，选择 revision rev_a，重点解释视频采集到显示的路径。
如果配置声明与我的描述不一致，请保留冲突并指出来源。
```

不清楚顶层或 revision 也可以开始；助手会从工程配置识别。若有多个候选且无法唯一确定，会列出差异并询问影响结论的选择。

## 2. 安装与准备

### 安装完整 Skill 目录

本仓库的 Skill 源码位于：

```text
skills/fpga-project-reader/
```

安装时复制整个 `fpga-project-reader` 文件夹，保留 `SKILL.md`、`references/`、`scripts/`、`assets/` 等内容。**只复制 SKILL.md 无法使用完整绘图能力。**

当前 OpenAI 官方文档列出的 Codex 本地 Skill 目录包括用户级 `~/.agents/skills/` 和项目级 `.agents/skills/`。Windows 用户级目录示例：

```text
C:\Users\<你的用户名>\.agents\skills\fpga-project-reader\SKILL.md
```

安装后，在 Skill 选择器中确认可见，再调用 `$fpga-project-reader`；未显示时可重启 Codex。调用入口随客户端不同，Codex CLI/IDE 支持 `$` 提及，ChatGPT 客户端支持 `@` 选择。[OpenAI 官方安装位置与调用说明](https://learn.chatgpt.com/docs/build-skills)

已安装可用时无需重复复制或创建同名副本。

### 从 GitHub 安装

在 Codex 对话中请求安装：

```text
请使用 $skill-installer 从 https://github.com/Petrichor223/fpga-project-reader/tree/master/skills/fpga-project-reader 安装 fpga-project-reader。
```

安装后开启下一次对话并使用 `$fpga-project-reader`。如果列表仍未更新，重启 Codex。本仓库的默认分支为 `master`。

### 准备工程材料

优先提供完整工程目录，包括工程文件、构建脚本、RTL、IP 配置、约束及测试入口。常见材料有：

| 工程类型 | 有帮助的材料 |
|---|---|
| Vivado | `.xpr`、Tcl、`.xdc`、`.xci`、`.bd`、相关源文件 |
| Quartus | `.qpf`、`.qsf`、`.qip`、`.ip`、`.qsys`、`.sdc` |
| 通用 RTL/仿真 | Verilog/SystemVerilog/VHDL、文件清单、Makefile、仿真脚本、testbench |
| 已有构建与验证结果 | 对应配置的展开/综合报告、可读取网表、时序报告、测试日志 |

没有工程文件、只有 RTL 也能做有限阅读，但有效顶层、宏、文件集和工具配置可能无法确认。不要用其他工程或旧 revision 的报告补成当前事实。

### 环境要求

- 需要能读取本地工程文件的 AI 助手；默认将报告写入工程目录，指定其他输出位置也可以。
- 普通静态阅读不要求安装 Vivado 或 Quartus。使用原生数据库、查询对象时才需要匹配版本的厂商环境。
- 生成交互框图和时钟树需要 Python 3；当前打包脚本使用标准库，交互运行资源已随 Skill 提供。
- 打开生成的 HTML 只需要浏览器。单文件页面可离线查看，不用启动服务器、运行 Python 或连接厂商工具。离线指生成结果的查看方式，不代表 AI 分析过程一定离线。
- 普通本地生成与校验由助手执行，无需用户逐个运行中间脚本；实际文件访问、网络和工具操作仍遵循环境权限。

## 3. 选择快速模式或详细模式

| 项目 | 快速模式：默认 | 详细模式：明确要求 |
|---|---|---|
| 目标 | 尽快建立工程框架 | 深入理解模块实现与相互关系 |
| 阅读范围 | 工程入口、有效顶层、主要子系统和代表实现 | 全部可解析实例，持续记录未读与不可见边界 |
| 模块说明 | 主要职责、上下游和来源 | 参数、接口、协议、状态机、延迟、限制等 |
| 时钟复位 | 主要域、来源、频率和关键连接 | 更完整的频率、消费者、复位及跨域台账 |
| 典型输出 | 一份 `OVERVIEW.md` | 总览、专题页面和逐模块说明 |

两种模式都附证据、保留未知，不同的是阅读范围与解释深度。快速模式不穷举所有叶实例，也不为生成完整索引扫描全部生成 IP。详细模式遇到加密实现、缺失依赖或无法展开的分支时，会记录边界，不承诺自动解析所有 HDL。

如果只想深入一个模块，可以直接提出定向问题，不必将全工程切换为详细模式。

## 4. 常用提问示例

以下路径为示例，使用时替换为真实目录。后续提问建议继续在同一对话中进行，保留已选配置。

### 完整详细阅读

```text
请使用 $fpga-project-reader，以详细模式阅读 D:/FPGA/MyProject。
确认有效配置，追踪所有可解析实例，输出模块说明、数据路径、
时钟复位、跨域连接、IP 边界和测试结构，并记录分析覆盖与未知项。
```

### 只解释一个模块

```text
请使用 $fpga-project-reader，沿用当前工程配置，深入解释 u_top.u_rx：
它的作用、输入输出协议、反压、参数、时钟复位和上下游连接。
只深入该子系统，不扩大为全工程详细分析。
```

### 生成可展开交互框图

```text
请使用 $fpga-project-reader，以快速模式阅读 D:/FPGA/MyProject，
并生成离线可展开框图。优先展示系统总线和板外器件，
允许展开本次已分析的主要子系统，查看内部 IP、接口和连接证据。
未分析或加密的内部请明确标记。
```

绘图前会检查已有编译产物。身份匹配且可读取时，优先采用展开阶段的真实层级与连接；无法使用时，回退到当前配置、Qsys/BD 和 RTL，并说明来源。找到数据库目录不等于已读取网表，也不会因此自动重编译。

### 生成时钟树

```text
请使用 $fpga-project-reader，沿用当前配置生成时钟树。
列出外部时钟、PLL/MMCM 输出、缓冲、MUX、分频和主要消费者，
区分时钟派生与分配路径，频率未知时不要猜测。
输出离线 HTML、SVG、可编辑 draw.io 和证据台账。
```

时钟树支持 Vivado/Quartus。没有厂商工具时仍可基于有效 RTL/IP/约束生成静态分析结果；原生查询脚本只查询已准备好的工具会话，不自动打开工程、加载约束或编译。

### 专门了解测试结构

```text
请使用 $fpga-project-reader，重点阅读 D:/FPGA/MyProject 的测试部分。
说明 DUT、激励、参考模型、checker/scoreboard、测试入口、通过条件及覆盖范围。
区分仿真测试、板级演示和已经运行过的验证结果。
```

### 自定义报告位置

```text
请使用 $fpga-project-reader，以快速模式阅读 D:/FPGA/MyProject，
将报告放到 D:/Reports/MyProject，保留 quick/reports 与 quick/data 分类。
```

## 5. 报告放在哪里、先读什么

默认写入被分析工程下的 `fpga-reader-report/`。以下是典型布局，按需求生成，空目录或不适用页面不一定出现：

```text
fpga-reader-report/
├── INDEX.md                         总入口
├── quick/
│   ├── reports/
│   │   ├── OVERVIEW.md              快速概览
│   │   ├── interactive.html         按需生成的交互框图
│   │   ├── clock-tree.html          按需生成的交互时钟树
│   │   ├── clock-tree.svg
│   │   ├── clock-tree.drawio
│   │   └── clock-tree.md            时钟与证据台账
│   └── data/                        JSON、清单、校验结果等
├── detailed/
│   ├── reports/
│   │   ├── CODEBASE.md              详细总览
│   │   ├── configuration.md         有效配置
│   │   ├── hierarchy.md             层级与实例
│   │   ├── signals.md               数据与控制路径
│   │   ├── clock-domains.md         时钟复位与跨域
│   │   ├── ip-and-libraries.md      IP、语言与库
│   │   ├── verification.md          验证结构
│   │   ├── evidence.md              证据索引
│   │   ├── open-questions.md        未知与冲突
│   │   └── modules/                 逐模块说明
│   └── data/
└── archives/                        按需保留的历史归档
```

详细模式也可在自己的 `reports/` 中生成交互框图和时钟树。建议阅读顺序是 **INDEX → 概览 → 关注的模块或专题 → 证据与未知项**。通常无需逐个打开 `data/` 中的 JSON/CSV。

同一目录可能保留历史报告，先看日期、配置和分析范围。文件名可能随定向任务增加；以 INDEX 中的实际链接为入口。

## 6. 如何使用生成的图

### 交互框图

用浏览器打开 `interactive.html`。默认以系统总线呈现主要接口；可展开/收起已打包的子系统、搜索实例、聚焦模块，并点击节点或连线查看功能、物理端口成员、方向及来源。支持在系统总线与接口明细之间切换。

时钟、复位和 PIO 默认保留。部分辅助系统 IP 可以默认隐藏，通过“显示辅助系统 IP”、层级树或搜索恢复；隐藏不等于未收录。图中颜色表示功能类别，不应直接解释为时钟域。

页面只展示本次已分析并打包的结构。点击展开不会启动新的源码分析；未读、黑盒和加密内部会明确标记，需要时再请助手定向阅读。

### 时钟树

用浏览器打开 `clock-tree.html`，搜索时钟，筛选派生/分配关系，显示或隐藏消费者，并查看频率与证据。查看静态图用 SVG；需要编辑节点和连线时，用兼容 draw.io 的编辑器打开 `.drawio`。

相同频率不等于同一时钟域；约束目标不等于板上实测；时钟对象的派生关系也不等于完整物理时钟网络。具体采用了哪类证据，以台账为准。

HTML 内嵌数据和资源，复制页面后仍可查看；源码证据跳转依赖原工程路径，工程移动或交给他人时应同时保留来源文件和位置说明。

## 7. 如何理解结论

| 标记 | 含义 | 示例 |
|---|---|---|
| 已确认 | 在指定配置和阶段有直接证据，或有可复算推导 | QSF 明确设置了顶层；PLL 参数声明某输出频率 |
| 推断 | 有实现依据的功能解释，但尚缺直接证明 | 某缓冲可能用于吸收两个处理阶段的速率差 |
| 未知 | 证据不足、冲突、不可见或尚未验证 | 板上实际频率、加密 IP 内部延迟 |

源码确认存在同步寄存器，不等于 CDC 验证通过；测试脚本存在，不等于测试已运行；图形结构校验通过，也不等于连接功能、时序或硬件已经验证。

默认阅读不改 RTL、工程配置或约束，也不自动完整编译、回归、升级 IP、生成 bitstream 或操作板卡。需要这些工作时，另行明确提出。

## 8. 常见问题

**为什么快速模式仍有未知项？** 该模式优先交付可核查的工程框架，不以消除全部未知为前提。可继续指定影响最大的疑点或模块进行深入阅读。

**为什么没有自动生成图？** 框图与时钟树都是按需功能。发送“请生成离线可展开框图”或“请生成时钟树”即可；两种图用途不同，可以同时保留。

**为什么某些 IP 不能展开？** 可能未分析、加密、缺失、黑盒或当前层级未打包，也可能只是折叠或被筛选。先看层级树、状态及隐藏数量，不要将无按钮理解为没有子模块。

**没有 Vivado/Quartus 还能使用吗？** 可以做静态阅读和绘图，但原生展开、时序及工具相关结论受限。缺少工具不会被写成编译通过。

**能直接打开所有 qdb、DCP 或厂商 IP 吗？** 不承诺。受版本、edition、阶段、身份记录和可访问接口限制；无法读取时会说明并采用可核查的后备材料。

**源码或工程位置变了，旧图还有效吗？** 旧图仍是历史快照。应重新核对受影响的配置、接口和输入身份后生成，不能只改日期。工程路径改变也可能影响输入校验与证据跳转，请在请求中提供新路径。

**需要手动安装 hdldiagzero 或 VLSIT 才能画图吗？** 本 Skill 当前交互框图和时钟树使用自带脚本与资源，不要求安装这些独立 Skill。它们是部分设计思路的参考，独立安装并不会替代本 Skill 的工程配置与证据核查。

**更新仓库里的 Skill 就等于更新了已安装版本吗？** 不一定。源码目录与用户安装目录可能是两份文件；更新后应确认实际调用的是哪份 Skill，并同步完整资源。不要直接覆盖人工修改。
