# FPGA Project Reader

帮助工程师回答：工程做什么、针对什么器件、实际编译哪些文件、各模块如何协作、有哪些时钟和复位、测试证明了什么。输出语言跟随用户，中文请求默认生成中文报告，保留代码标识符原文。

## 模式选择

- **快速模式（默认）**：用户只说“阅读/分析工程”或未指定深度时使用。读取构建入口、有效顶层和主路径代表文件，交付一份有证据的概览；不要求穷举文件、展开全部叶实例或生成逐模块页面。按 [quick-mode.md](references/quick-mode.md) 的步骤和停止条件工作。
- **详细模式（显式选择）**：用户要求“详细模式”“完整逐模块分析”等完整深入报告时使用下方详细流程。定向深入某一模块只扩大该问题的范围，不自动转为全工程详细分析。
- 报告开头标明模式、配置和覆盖边界。模式决定阅读范围，不降低证据标准。工程大、存在未知或未读模块，都不是自动升级详细模式的理由。

## 工作边界

- 默认读取工程，写入独立报告目录；不修改 RTL、约束、工程配置或已有手写文档。报告默认放在工程根目录的 `fpga-reader-report/`，用户指定位置时遵从；按 [report-format.md](references/report-format.md) 区分快速/详细、阅读报告/分析数据，不把 JSON、CSV、日志散放根目录。目录已有内容时先辨别生成文件与人工维护内容，避免覆盖人工修改。
- 复用历史报告须说明来源、日期和与当前输入的匹配性，不能把历史结论直接标为本次已验证。快速模式不以安装工具、全量展开为交付前提。
- 可以读取已有构建产物。工具可用且权限允许时，优先用与目标配置匹配的原生工程查询或 elaboration 校核静态分析。打开工程也可能产生锁、日志或迁移，优先使用工程副本或隔离输出目录。
- 仅为阅读工程，不自动完整编译、运行回归、升级 IP、生成 bitstream 或操作板卡。用户已要求相关操作时依其授权执行；缺少工具或依赖时继续静态分析，并说明验证边界。
- 不强制命名规则、目录布局、复位方式或“一个文件一个模块”。不假定用户拥有特定厂商软件、许可证、MCP、LSP 或其他 Skill。

## 按模式分析与按需参考

先阅读 [evidence.md](references/evidence.md) 与 [report-format.md](references/report-format.md)，统一结论状态、证据定位、配置身份和输出位置。快速模式随后执行 quick-mode 的有限流程，不要求先读取全部专业参考文件。以下步骤的完整度要求只适用于详细模式；快速模式遇到具体疑点时按需查阅对应参考。

1. **确定分析对象与有效配置。** 阅读 [project-configuration.md](references/project-configuration.md)。从工程元数据、构建入口、文件清单确定器件、revision、顶层、文件角色、宏、库及 include 路径。目录中出现一个文件不代表它参与构建。发现多个目标时先列配置矩阵；无法唯一选择时继续共同部分，向用户询问会改变结论的配置。不得默选名称最像顶层或时间最新的文件。
2. **建立实际层级，再解释功能。** 从所选配置的顶层追踪全部可解析实例；区分源代码模块定义与经过参数、generate、预处理后形成的实例。用实例路径标识实例，用语言/库/源码位置标识定义。同名模块、不同 VHDL architecture、不同参数实例不可合并成一个结论。记录未绑定实例、递归/工具限制与覆盖进度，不以预设层数截断。
3. **解释模块与主要数据路径。** 按 [module-analysis.md](references/module-analysis.md) 读取实现与依赖，形成逐模块说明。模块多时先输出全量索引，再分批补充详细说明并记录缺口；不能把未阅读模块列为已分析。
4. **追踪时钟与复位。** 按 [clocks-and-resets.md](references/clocks-and-resets.md) 对照 RTL、IP 配置、约束和工具结果，建立源头到实例的时钟链与跨域连接。频率无法确定时明确写“未知”，不要根据名称或注释补值。用户要求时钟树时执行下方时钟树功能，范围仍由当前模式和定向问题决定。
5. **处理 IP 与混合语言。** 遇到 VHDL、BD、Platform Designer、加密/缺失 IP 或黑盒时，阅读 [ip-and-mixed-hdl.md](references/ip-and-mixed-hdl.md)。把可见接口、配置意图与不可见实现分开。
6. **解释验证结构。** 存在仿真、板级测试、UVM、cocotb、形式验证或相关脚本时，阅读 [verification.md](references/verification.md)。即使目录名为 `test`，也先确认是仿真工程、上板测试设计还是生产设计。
7. **组织与自查报告。** 使用 [report-format.md](references/report-format.md) 的结构；定向问题可缩减报告，但仍给出配置身份、证据、未知项和覆盖边界。图中的节点、时钟、连线必须与表格和证据一致。

## 执行方式

- 先检查本地工程指令，搜索工程入口和清单，再读取相关源文件。优先 `rg --files`、`rg -n` 和已有 HDL parser/LSP；搜索命中是定位手段，不是完整语法或 elaboration 证明。
- 对 `.tcl`、`.qsf`、`.f` 等递归追踪 include/source、相对路径基准、条件分支和命令行覆盖。未经求值的变量、动态文件选择或缺失依赖进入未知清单，不通过运行任意仓库脚本来“猜测”配置。
- 工具命令随厂商和版本不同：先检查安装版本、工具帮助或匹配版本的官方文档再使用。完整记录查询对象、配置和工具输出路径。不要把一个厂商的对象属性或命令直接用于另一个厂商。
- 详细模式对大型工程维护配置索引和覆盖表，沿顶层先读控制/数据主路径，再读叶模块及验证代码。快速模式只记录已读关键入口与未检查范围，达到概览要求即交付，不先补做详细模式任务。工具无法处理的语法以源码核查补足，并说明剩余边界。
- 除非用户授权或当前环境明确允许，不依赖并行子代理；单代理也应能完成全部流程。

## 交互框图（按需）

用户要求框图、展开/收起、查看子系统内部 IP 时，阅读 [interactive-diagrams.md](references/interactive-diagrams.md)。用本 Skill 自带的离线查看器交付 `reports/interactive.html`，配套数据与校验结果放同一模式的 `data/`。普通工程概览不强制增加交互图，也不为了绘图扩大快速模式阅读范围。

- 采用 hdldiagzero 的分层、接口分组和隐藏辅助信号思路，交互与布局使用已打包的 d3-hwschematic / ELK；不把静态 SVG 上的显隐操作当作正确的跨层连接展开。
- 生成前先按 [compiled-rtl.md](references/compiled-rtl.md) 检查已有 RTL Viewer / Analysis & Elaboration 阶段产物；配置和输入身份匹配且可读取时，优先采用该阶段的真实层级、端口及连接，结合源码解释功能。目录或报告存在不等于已提取网表；过期、打不开或不含连接时注明原因并回退，不自动重编译。
- 默认交付系统总线视图：将有证据的板外传感器、存储器、收发器与 FPGA 边界明确画出；用一条逻辑总线表示一个接口，握手、响应和物理引脚放入线路详情。用独立 `presentation` 层保留真实 RTL 树和原始连接，支持切换接口明细。外部器件不能冒充 RTL 实例，不能为简化而合并无关接口。
- 先确认所选配置与实例/端口/连线证据，再生成结构数据。保留稳定的父接口和到直接子实例的真实信号映射，反压/响应方向分别记录；不得凭模块命名编造连线或加密内部。
- 快速模式只展开本次已读的主要子系统；未读/加密/缺失内部显示明确标记，不能把无展开按钮解释成没有子模块。详细模式仍按证据逐层扩展，不承诺自动解析所有 HDL。
- 纳入图中的容器核对并保留全部直接 IP 数据。时钟、复位、PIO 框体及有证据的连接默认显示；区分 PIO 的寄存器总线与引脚导出。sysid/systemid、timer 等辅助系统 IP 可明确标记后默认隐藏，提供恢复开关、隐藏数量及树/搜索入口，不计作缺失。未连、常量或未知不能靠虚构连线消除。详细规则见交互参考。
- 用 `scripts/build_interactive.py` 一次完成结构校验与 HTML 打包；由代理自动执行任务内普通本地步骤，不要求用户逐一运行脚本。查看、搜索和展开图不运行 Python、不联网、不依赖厂商工具。首次补依赖、写入受保护目录等仍遵循实际环境权限，不能通过脚本绕过。

## 时钟树（按需，Vivado / Quartus）

用户要求绘制时钟树、时钟拓扑或 PLL 到模块的分配图时，阅读 [clock-tree.md](references/clock-tree.md)。普通快速概览不强制生成图，也不为了画图自动完整编译或扩大阅读范围。

- 统一数据表达时钟源、PLL/MMCM 输出、缓冲、MUX、门控、分频、消费者及虚拟/未知时钟；区分时钟派生关系与实际分配路径。节点、连接和每项频率分别附状态与证据，保留多源、反馈、动态模式和冲突频率。
- Vivado/Quartus 原生查询与无工具静态阅读使用同一模型。原生入口与边界见 [clock-tree-vendors.md](references/clock-tree-vendors.md)，模型见 [clock-tree-schema.md](references/clock-tree-schema.md)。自带 Tcl 只查询已准备好的会话；时钟对象导出仅建立派生关系，不冒充完整物理时钟网络。
- 代理自动运行 `scripts/build_clock_tree.py <model.json> --output-dir <mode-dir>`，校验输入身份和结构后生成 `reports/clock-tree.svg`、`.drawio`、`.html`、`.md`，机器数据和校验日志留在同模式 `data/`。离线 HTML 支持搜索、关系筛选、消费者显隐和证据查看，无需安装绘图库或联网。
- 无厂商工具时依据有效 RTL/IP/约束绘制，并声明未验证范围；不因频率相同认定同域，不把约束目标当板上测量，不将图形校验等同 CDC/时序签核。导航链接到当前实际生成文件，保留已有交互框图与手写文档。

## 完成检查

- 模式是否符合请求，默认是否确为快速？范围与产物是否与模式一致？文件是否位于对应模式的 reports/data 目录，导航是否有效？

- 器件、顶层、revision 和有效文件集是否有来源？备份、未激活源文件、仿真文件是否分开？
- 详细模式：所有可达实例是否已追踪？同一模块的不同参数实例、条件分支和无法解析实例是否明确？快速模式不以全量追踪作为交付条件。
- 每项实质结论是否标注“已确认 / 推断 / 未知”并可追溯？与其他证据冲突的项目是否保留？
- 所分析的时钟是否追到来源，频率是否有依据和适用配置？详细模式检查完整台账，快速模式声明只覆盖主要域。复位释放及 CDC 是否区分结构观察与验证结论？
- 模块说明是否能帮助工程师理解功能、协议、延迟、配置顺序和限制？
- 验证报告是否区分测试存在、测试运行和覆盖达标？
- 报告是否诚实列出未读、缺失、加密、未展开、未运行及不适用部分？
- 若生成交互图：父子接口映射、反压方向和结论状态是否可核查？展开/收起后连接是否保留？有浏览器验证条件时检查实际交互及离线运行；没有时交付结构校验结果并注明尚未进行浏览器验证。
- 若生成时钟树：是否区分派生与分配、虚拟与物理、配置/约束/工具/实测频率？多源、反馈和冲突是否保留，配置/阶段/输入匹配性是否有证据？原生查询未运行时是否明确说明？
