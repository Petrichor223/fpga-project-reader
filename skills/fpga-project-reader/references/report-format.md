# 报告结构与交付规范

## 两种模式与文件分类

默认快速模式。根目录只保留导航 `INDEX.md` 和分类目录；可阅读 Markdown 放对应模式的 `reports/`，JSON、CSV、解析索引、输入快照、工具输出和日志放 `data/`。不为凑结构生成空文件；快速模式通常不需要 data。多个配置在对应 reports/data 下使用相同配置子目录。

```text
fpga-reader-report/
  INDEX.md
  quick/
    reports/
      OVERVIEW.md
      interactive.html          # 请求交互框图时生成；单文件离线浏览
    data/                       # 有必要才创建
      architecture.json         # 交互层级、端口映射与证据；按需
      interactive-validation.json
  detailed/
    reports/
      CODEBASE.md
      interactive.html          # 请求交互框图时生成
      configuration.md
      hierarchy.md
      signals.md
      clock-domains.md
      ip-and-libraries.md
      verification.md
      evidence.md
      open-questions.md
      modules/
        <unique-definition-id>.md
    data/                       # JSON、CSV、清单、工具日志等
  archives/                     # 用户需要归档或保留旧压缩包时创建
```

`INDEX.md` 链接实际存在的模式入口，注明分析日期、配置、静态/工具验证边界。未生成详细报告时标“尚未生成”，不要创建误导性的链接。切换模式保留另一模式已有结果，不自动重跑或覆盖它。

交互图规则见 [interactive-diagrams.md](interactive-diagrams.md)。HTML 内嵌结构数据与运行库以支持 `file://` 离线查看；可重建的原始 JSON、哈希和浏览器检查结果仍放 `data/`，不另创建一套混淆模式的 diagrams 根目录。历史静态图可保留并添加导航，不能用新图的验证日期替换历史报告身份。

按需时钟树遵循 [clock-tree.md](clock-tree.md)：可读的 `clock-tree.svg`、`clock-tree.drawio`、`clock-tree.html`、`clock-tree.md` 放当前模式 `reports/`；`clock-tree.json`、原始厂商导出、context 与 `clock-tree-validation.json` 放对应 `data/`。从当前概览/时钟页面及 INDEX 链接真实产物，不覆盖手写文档、不混合配置或改写历史报告身份。

快速模式的 `OVERVIEW.md` 包含：模式与范围、用途/主路径、有效配置摘要、主要模块表、主要时钟复位表、测试结构和关键未知。证据在结论旁直接定位或使用小型内嵌索引；通常只交付这一份阅读报告，不执行下方详细文件的全量要求。

## 详细模式页面要求

以下页面用于详细模式，内容很少时可合并；无关章节在总览说明“不适用/未发现及搜索范围”。

模块页面文件名需要消除库、architecture、同名源文件的冲突；在索引中映射原始标识符。不要直接把包含路径分隔符的实例名当作输出路径。

需要详细 FSM、package/type/interface、函数、宏或约束分析时增加相应页面并由总览链接；小工程可放入模块说明或 configuration 页面。保留 gf-architect 风格的分层导航，不要求输出与工程无关的固定章节。

## CODEBASE.md

开头直述用途和主要数据路径，标明结论状态。接着提供：

- 分析身份、配置矩阵与所选范围；关键工具及静态/原生展开/工具验证的可用程度。
- 综合顶层、仿真顶层、器件及 revision；源文件/定义/实例/时钟数量，未知或不完整时显式标注。
- 系统结构图、数据输入到输出的路径、控制/配置路径。
- 全量模块索引：定义 ID、名称/库/architecture、用途、实例位置/数量、覆盖状态、详细页面。
- 主要时钟与复位概览、关键 IP、测试入口、主要限制与各详细页面链接。
- 分析覆盖：解析过的配置/清单、已展开/已详读部分、缺失或不可见部分，以及本次未执行的验证。

## configuration.md

记录器件 family/part/package/speed（能确认多少写多少）、board（不由 part 推断）、工具/版本、revision、顶层、文件集、宏/include、库/编译顺序、参数与入口调用链。

附有效文件清单及激活状态、未引用/禁用/条件未决文件、仿真替代实现、IP 与约束引入链。不同配置差异单独列出。

## hierarchy.md / signals.md

层级用 `实例路径 → 定义 ID → 生效参数 → 时钟/复位 → 实例化证据`。图可折叠重复阵列，表格保留范围和差异； unresolved/blackbox 明确标出。

信号说明主要控制/数据路径、协议、宽度、驱动/消费端及关键跨层连接。图中方向应是实际数据或控制关系；不要让“包含关系”箭头同时代表数据流。

## clock-domains.md

时钟来源树、频率台账、时钟域到模块映射、复位台账和释放依赖、跨域连接表、约束/例外及与工具结果的差异。频率必须带来源性质、单位和状态；不确定的值写“未知”。引用 clocks-and-resets 规定的字段。

## modules/*.md

每页涵盖：功能与系统位置、定义及实例变体、参数/generic、端口/接口、子实例、时钟复位、行为/协议、数据路径与延迟、FSM（适用时）、寄存器映射（适用时）、使用限制、测试关联、未知项和证据。

表格可共用证据索引；公共时钟和 IP 说明链接到主页面而不重复。实现不支持某信息时写未知/不适用及原因。对定向分析可只输出用户关心的模块，但声明范围。

## ip-and-libraries.md / verification.md

IP 表记录身份/版本、配置、实例位置、接口、生成/可见性、依赖和受限结论；混合语言记录库、绑定和编译顺序。

验证页面提供测试结构图、入口及配置、DUT、激励/模型/checker/scoreboard、通过条件与退出码链、场景覆盖、已有运行/覆盖结果及其匹配性。仿真、形式与板级测试分开。

## evidence.md / open-questions.md

证据表：`证据 ID | 配置 ID | 来源类型 | 路径/结构定位/行号 | 支持的事实 | 阶段/匹配性`。

未知/冲突表：`条目 ID | 问题 | 状态/影响范围 | 已检查范围/冲突证据 | 所需最小信息或后续动作`。不是所有未知项都需要用户立即回答；优先询问改变顶层、有效文件集和主要时钟结论的关键项。

正文中的结论示例（演示格式，不是目标工程事实）：

- `已确认：CFG-01 将 rx_word 写入异步 FIFO 的写端 [E012,E019]。`
- `推断：此路径用于吸收输入与系统域的速率差异；依据为双时钟连接和 ready 反馈 [E012,E020]，缺少系统规格。`
- `未知：板上 ref_clk 实际频率；只见 10 ns 约束 [E023]，未提供板卡时钟资料。`

## 既有平铺报告的整理

用户要求整理时，先辨别生成文件与人工内容。既有完整报告迁入 `detailed/reports/`，机器数据迁入 `detailed/data/`，已有压缩包放 `archives/`。按每个旧链接原本指向的目标重新计算相对路径，包括跨报告、data、源码及证据锚点；不能只搬文件而留下失效链接。保留数据字节内容和历史分析身份，不把整理日期写成重新分析日期。不要合并不同配置的数据。

可以基于既有报告增加快速摘要，但必须在开头注明“历史详细报告摘要，未重新分析当前源码”。用户未要求重新阅读时，不为整理目录重新扫描或运行整个工程。

## 最终检查与交付

检查实际生成页面的本地链接、配置分离、证据定位、时钟单位及表图一致性；仅详细模式要求全量定义/实例计数与覆盖表。整理时验证机器数据未变、原文件均有去向、源码链接仍指向原目标。只有匹配配置且实际运行过的检查才写为已通过。

交付总览的可点击路径、简短工程结论和最影响理解的未知项。不要将工程说明包装成 signoff、完整功能证明或实际硬件验证。
