# 快速模式：优先建立工程框架

目标是尽快让工程师知道“是什么、从哪里看、主要模块怎样连接、时钟复位和测试大致怎样工作”。默认只生成一份 `quick/reports/OVERVIEW.md`，不生成逐模块页面。

用户要求交互框图时额外交付 `quick/reports/interactive.html`，遵循 [interactive-diagrams.md](interactive-diagrams.md)；仅将本次已读层级打包到 `quick/data/architecture.json`。页面中的展开仅切换已打包结构，不触发进一步工程阅读；未读内部显示“尚未分析”，需要更多层级时再定向补充数据。

用户要求时钟树时按 [clock-tree.md](clock-tree.md) 额外交付 `quick/reports/clock-tree.*` 和对应 data，覆盖已追踪的主要时钟及明确的定向范围；不要求完整扫描每个寄存器负载或启动编译。

## 有限阅读顺序

1. 找工程入口和候选配置。读工程元数据/主要清单，确认或明确标未知：器件、有效顶层、revision、设计/仿真文件集、主要宏/include。多配置未选定时说明候选与共同范围，不能根据名字或时间擅选。
2. 读有效顶层、主数据路径和控制入口。为主要子系统列用途、上下游和源码位置；按理解用途所需读取代表实现。厂商 IP 先看接口和核心配置，不逐页读取生成 HDL、全部端口和所有参数。
3. 查主要时钟/复位的 RTL 连接、PLL/MMCM 配置与已引用约束。用紧凑表列来源、配置/约束频率、主要消费者、派生关系和重要跨域连接；无法确认写未知。只说明已追踪的主要域，不声称完整时钟/CDC 清单。
4. 查测试入口和相关文件。概述 DUT、激励、参考模型/scoreboard、通过条件和覆盖范围；缺少材料时写“在已检查范围未发现”。区分板级演示与自检查仿真，不能用生成的 IP 仿真脚本证明端到端验证。
5. 交付概览：用途、配置摘要、框图/主路径、主要模块表、时钟复位表、测试结构、关键未知和阅读边界。小工程可合并章节。实质结论附源码位置或共享证据，不必另建证据文件。

## 控制耗时与停止条件

- 达到上述概览覆盖即可交付。未影响概览的叶实例、完整宏分支、所有备份文件、全量层级和详细协议/状态机留在边界说明，不先补齐再交付。
- 不为快速阅读扫描整个版本控制数据库、哈希全部工程文件、生成全量结构 JSON 或全量厂商 IP 参数转储；只记录关键入口/源码身份，按需保存少量可复用数据。
- 有历史详细报告时可作为定位线索。核对相关配置及关键输入；未核验的历史内容保留历史身份。若用户只要求整理报告，可生成明确标为“历史报告摘要”的快速概览，不能声称重新分析了当前工程。
- 遇到工具缺失、长生成链或加密实现，不把安装依赖、全量展开或解密作为前置。报告当前已知和最关键缺口。
- 只为会改变工程用途、有效顶层或主要时钟判断的阻碍继续定向核查；其余未知在概览内列出。不要为了消除所有未知而静默进入详细模式。

## 最小交付标准

有来源的配置身份、用途/主路径、主要模块职责、主要时钟复位、测试性质，以及未读/未运行范围。不能确认的字段可以为未知，不能省略边界或将抽样阅读写成完整分析。
