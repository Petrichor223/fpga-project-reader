# 模块功能、层级与连接

## 定义和实例

定义用 `语言 + 库 + entity/module + architecture（适用时）+ 源位置` 标识。实例用完整层级路径标识，保留 generate 索引和所用配置。一个定义可写一份公共说明，再为不同参数、generic、architecture 或宏分支列实例差异。

对每个父子关系核对实例化位置、绑定定义、端口映射、参数/generic 覆盖。位置连接要映射回声明顺序；隐式 `.*`、同名端口、省略/未连接端口和默认参数也要检查。不要仅凭实例名前缀匹配；同一文件允许多个定义。

沿上下游两端核对跨模块信号：驱动位置、组合/寄存器、消费位置、握手条件和所属时钟。连接名相同不等于同一个全局信号，名称不同也可能只是层级别名。综合后的重命名/优化需和源码层级分开。

## 逐模块说明

以下是适用内容的检查清单，无关部分标不适用而不编造接口：

| 内容 | 从哪里确认、需要解释什么 |
|---|---|
| 功能与系统位置 | 由实际数据/控制路径说明输入如何变成输出、谁配置谁；注释与 README 作为意图线索 |
| 参数/generic | 声明默认值、该实例有效值、依赖表达式及实现中可证明的合法约束；未验证范围不要扩展为任意合法值 |
| 端口和接口 | 每个端口的方向、实际位宽/类型、协议角色、时钟域和连接对象；位宽未知时保留表达式 |
| 子实例 | 定义、实例位置、参数差异和职责；公共说明链接到子模块页面，避免重复全文 |
| 时钟/复位 | 引用统一时钟 ID；同步/异步、极性、各状态或输出的复位行为、未复位数据的有效条件 |
| 传输协议 | 实现的接受/完成条件、valid/ready/req/ack、背压、丢弃/重试和缓冲；不要由信号名称直接断言符合标准协议 |
| 数据路径 | 位宽转换、符号、截断/舍入/饱和/回绕、FIFO/存储器组织、边界行为 |
| 时序行为 | 定义延迟起止事件，区分最小/固定/可变延迟、吞吐、启动间隔、停顿和跨时钟域等待 |
| FSM | 实际状态寄存器、编码、转移条件、输出动作、异常状态、超时及启动顺序；状态图与 RTL 一致 |
| 寄存器映射 | 实际地址译码、字节/字地址、访问宽度、字节使能、复位值、读写副作用、地址别名 |
| 使用限制 | 配置何时采样、输入稳定要求、合法序列、溢出/欠读/非法命令等实现可见行为 |

接口表和实例模板必须从声明核对，不从文档草案补全。需要实例模板时按目标语言及实际有效参数生成；不是所有模块报告都必须带模板。

## 容易错误解释的细节

- 多个非阻塞赋值在同一边沿读取旧值；不能按源码顺序当成多个周期或组合串联。组合 bypass、FIFO FWFT、同步 RAM 和 output register 会改变实际延迟。
- latency 必须给出条件，例如“接受输入到输出 valid，持续 ready 时 N 个 sys_clk 周期”。跨域路径不能不加条件地合并成一个周期数。
- 寄存器读写类型由实现推导：读清零、写 1 清零、自清零、只写命令和 shadow 更新不可仅靠名字判断。被 RTL 读写的内部寄存器不一定是 CPU 可访问寄存器。
- 声明了端口/状态不代表逻辑已实现。空模块、常量输出、仿真替身及未填骨架说明为实现缺口或替代模型。
- 无法看到子 IP 实现时，可以说明外部可观察协议与配置意图，不得宣称其内部算法、缓冲深度或延迟已被 RTL 证实。

## 工程功能综合

从顶层接口、实际数据流、控制路径和测试入口归纳用途。分别写“实现可证明的行为”和“由接口/项目说明推断的应用场景”。模块名叫 `adc_test` 不能单独证明采样率、测试精度或目标板型号。

大型重复阵列可以在图中折叠，但索引保留实例范围、参数差异、时钟归属及未展开原因。报告应能从总览导航到任意已分析实例和证据。
